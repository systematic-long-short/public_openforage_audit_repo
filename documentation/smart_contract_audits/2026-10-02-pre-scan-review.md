# Whole-source pre-scan review and proof limits

This is OpenForage's own source review of the public contract candidate. It is not an Octane result, an Octane finding closure, a deployment approval, or a security-clearance claim. No Octane scan or public write is part of this update.

## Candidate and scope

This update is based on the published PR #9 head `01f4abe7768f03d2a21e6ab0a0221795d315d79b`; its parent `6efd4cd86a9b2fec7f484c0da073f71385900308` and older commits are historical. The explicit public map has 61 paths: 35 Solidity source, interface, library, and module files; 18 ABI files; and 8 selected deployment-script/interface files. It deliberately includes `IAtRiskUSDProfitClaims.sol`, `AtRiskUSDProfitModule.sol`, `USDCTreasuryAccountingModule.sol`, `GuardianAuthorityClassifier.sol`, and the newly mapped `IRISKUSDSettlement.sol`; GuardianAuthorityClassifier was already present in this public base. `ForageGovernorTimelockMigrationGuard` is declared inside the mapped `ForageGovernorTimelockGuard.sol`; both linked libraries are pinned in the public Default and Deploy profiles. Two root dependency Gitlinks and nine recursive Gitlink pins are retained. Private audit records, scanner metadata, run logs, packet records, deployment state, credentials, other scripts and tooling, and all first-party contract test paths are excluded.

The source sweep was organized by contract family. Each repair listed below received an independent source review; `ACCEPT_BOUNDED` accepts only its named source slice and never means that an Octane finding was resolved. A completed review can also reject an earlier candidate, in which case only a later accepted correction is described as current. The sweep records preserve one attempt with no retained findings list as unavailable; its missing output is not treated as an empty result.

## Declared limits retained before the full scan

Each item below is a limitation or source boundary, not a finding closure. The size and ABI statements are rebound to this public candidate; the seven historical storage divergences are not waived.

2. **Historical storage baseline:** seven stored-layout comparisons remain divergent. They are historical baseline differences, not a fresh storage pass; no baseline was edited to erase them.
3. **Fresh-only deployment:** funded legacy-proxy upgrades are unsupported. The implementation already installed authorizes the first upgrade; once the new implementation is active, state-changing routes must refuse pre-fresh state before their own writes. No legacy migration or deployed-proxy identity is proved.

## Founder decisions in plain language

- **Founder decision 17:** exactly one full-source Octane scan may be run against a new PR #9 commit, only after the team is satisfied the pre-scan has eliminated the known defects. A full scan covers the whole source, not just the diff. This document is OpenForage's review, not that scan.
- **Founder decision 18:** add the missing first-party contract source files to the saved targeted scope before that scan. The public map in this update lists every current first-party source/interface/library/module and ABI file; it does not itself run or authorize the scan.
- **Founder decision 19:** retain the accepted floor-rounding behavior for closed-epoch profit. Up to one raw unit per holder per payout epoch can remain in funded reserve; no holder is overpaid and no claim can exceed the funded reserve. This is a declared limit, not a cross-cohort transfer request.

## Dropped work and bounded checker controls

The proposed hardening for the privileged loss-reporter route was rejected and dropped. The owner must keep the Vault loss reporter aligned with the custodian Bridge Treasury route at initialization and across handoffs; a mismatch stalls attested-loss settlement and leaves exits frozen until the owner repairs it. No public source fix or Octane disposition is claimed for that privileged configuration limit.

Two checker-control limits are retained rather than described as whole-call proof. The CREATE2 rule-coverage checker proves the library setup calls are direct, unconditional top-level statements in their functions and checks code length/hash there; it does not traverse every modifier, implementation, or helper call site in Deploy. The Timelock-acceptance control verifies that parsed comparisons bind to the pending pointer and precede writes in the recognized shapes; it does not prove that this is the unique reachable guard. Future additions outside those checked shapes are caught only by source review. These are checker limits, not Solidity defects, and the related bounded controls were independently reviewed.
